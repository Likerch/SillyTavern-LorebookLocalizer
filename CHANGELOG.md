# История версий

## 0.4.0 — русская поддержка LoreBook Creator

Если рядом установлен [LoreBook Creator](https://github.com/virgilianshailer/lorebook-creator) (проверено с 1.15.0),
в блоке Localizer в Extensions появляется раздел «LoreBook Creator». Подробно — в
[docs/lorebook-creator.md](docs/lorebook-creator.md).

- **Чистый канал генерации.** Раньше каждый запрос LBC уходил как ход RP: пресет, вся история чата, все лорбуки
  (с запуском таймеров sticky/cooldown в чате) и вставки других расширений. Теперь — только правила и сама просьба
  LBC, через профиль подключения (по умолчанию — тот же, что для ключей) или текущее подключение. Без рассуждений,
  со своими лимитом ответа, таймаутом и температурой. Макросы `{{user}}`/`{{char}}` доходят до модели как есть.
  Пустой ответ, не JSON или JSON не той формы — ошибка с причиной, а не «0 entries generated!» с очищенным
  редактором.
- **Язык записей**: английский с русскими ключами (по умолчанию), русский или язык идеи — переключатель в шапке LBC.
  Категории всегда остаются английскими названиями LBC, русские из ответа переводятся обратно.
- **Сохранение без потерь.** «Сохранить в ST» и «Скачать JSON» сохраняют название как есть (кириллица больше не
  превращается в `____`), спрашивают перед перезаписью, делают бэкап, обновляют список книг и сохраняют uid,
  `extensions`, роли, фильтры, триггеры и нули в depth/order/probability.
- **Русские ключи.** Кнопки в LBC добавляют все словоформы к ключам записей прямо в редакторе — тем же конвейером
  и предпросмотром, что у Localizer, в том числе к русским ключам. Перед сохранением в ST — вопрос о недостающих
  формах. В аудите LBC — русский раздел. Словоформы, которые выкинули «Оптимизировать» или «Правка моделью» LBC,
  возвращаются при сохранении.
- **Русский интерфейс** LBC (окно, окна, вопросы) и скрытая кнопка машинного перевода.
- **Черновик**: работа в LBC переживает перезагрузку страницы.

## 0.3.0 — ожидание ответа, отмена и ход работы для Maestro

- **Зависший запрос больше не держит расширение.** Раньше, если модель не отвечала, перевод ждал вечно, а с ним и
  все следующие запуски — и из окна, и от Maestro. Теперь запрос без ответа за 90 секунд прерывается и повторяется,
  как при ошибке (столько раз, сколько указано в «Повторов при ошибке»). Если ответа нет и после повторов, записи
  попадают в «Не переведено» с причиной «no reply in 90 s». Время меняется в «Запросах» → «Ожидание ответа,
  секунд», `0` — ждать без ограничения.
- **«Стоп» больше не обрывает ответ в чате.** Через текущее подключение кнопка «Стоп» останавливала всю генерацию
  SillyTavern, в том числе ответ персонажа, если он шёл в это время. Теперь «Стоп» и таймаут прерывают только запрос
  самого расширения; генерация в чате и запросы других расширений не трогаются. Новый запрос через текущее
  подключение не начинается, пока не завершился предыдущий, поэтому длина ответа в настройках не сбивается.
- **Очередь с Maestro понятнее.** Если Maestro как раз переводит записи, кнопка расширения так и говорит. Если
  Maestro начал перевод, пока было открыто окно выбора лорбуков, запуск из окна подождёт его конца, и об этом
  появится уведомление.
- **API для Maestro** (версия 1, только добавления; подробнее — в
  [README](README.md#api-для-других-расширений)):
  - `localizeEntries` принимает `onProgress` — ход работы в записях с фазами `queued` (ждёт другую задачу),
    `running` и `saving`;
  - `signal` отменяет задачу: идущий запрос прерывается, готовые пакеты сохраняются, Promise выполняется с
    `cancelled: true`; задача, которая ещё ждёт очереди, снимается сразу;
  - `batchTimeoutMs` — ожидание ответа на запрос, по умолчанию из настроек окна (90 секунд);
  - в результате появился `failed`: записи без ключей и причина — `timeout`, `invalid` или `error`. `failures`
    теперь равно `failed.length`: к записям, которые модель не перевела, добавились записи, у которых ни один
    вариант перевода не дал корректного ключа;
  - `busy()` и `onBusyChange()` говорят, занят ли Localizer и кем: окном (`dialog`) или вызовом API (`api`);
  - `features` — список возможностей для проверки: `progress`, `cancel`, `busy`, `timeout`.

## 0.2.0 — API для Maestro

- `globalThis.LOREBOOK_LOCALIZER_API`: сборка regex-ключей из словоформ (`buildKeyRegex`, `buildPlainKeys`,
  `cleanForms`), локализация выбранных записей без окон (`localizeEntries`) и проверка лорбуков BunnyMo
  (`isProtectedBook`).
- Основной лорбук BunnyMo и его паки узнаются по содержимому и не локализуются: в окне они выключены, пока это не
  разрешено в «Параметрах», через API — никогда.
- Окно и API работают строго по очереди.

## 0.1.0 — первая версия

- Перевод ключей лорбуков с помощью LLM и regex-ключи на все словоформы, сразу для нескольких лорбуков.
- Предпросмотр перед записью, резервная копия, удаление добавленных ключей.
