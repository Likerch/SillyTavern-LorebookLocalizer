# Разведка: LoreBook Creator и русский язык

Этап 0 модуля «LoreBook Creator» в Lorebook Localizer. Здесь собрано, как устроен LBC, что в нём мешает русскому RP
и через какие точки модуль будет с ним работать. Всё, что помечено **[стенд]**, проверено вживую на ST 1.19.0 с
полным набором соседей (DES, DES-RU, CarrotKernel, BunnyMo, NAI Studio, Qvink, Maestro) и mock-моделью. Остальное
взято из кода.

## 1. Что это

- [LoreBook Creator](https://github.com/virgilianshailer/lorebook-creator) 1.15.0 (`d17c069`), MIT. Папка
  расширения — `lorebook-creator`, `loading_order` 21.
- Весь код — один `index.js` на 4418 строк плюс `style.css`. Скрипт загружается как ES-модуль, поэтому всё внутри
  (`UI`, `PROMPTS`, `normalizeEntry`, `genQuiet`…) снаружи недоступно и подменить это нельзя.
- Копия для чтения лежит в `vendor/lorebook-creator` (в git не попадает).
- В `window.LorebookCreator.version` записано `'1.12.0'` при манифесте 1.15.0. Версию надо брать из манифеста.

## 3. Как LBC генерирует

LBC вызывает `generateQuietPrompt(prompt, false)`. В комментарии сказано, что `false` отключает системный промпт и
персону. На самом деле второй позиционный аргумент — `quietToLoud`, а `skipWIAN` остаётся `false`. Получается
обычный ход RP с тихим промптом в конце.

**[стенд]** Одно нажатие «Generate» в простом режиме на эталонном чате (668 сообщений, контекст 64K):

| | Без модуля | Прототип чистого канала |
| --- | --- | --- |
| Сообщений в запросе | 22 | 2 |
| Символов | 178 597 | 1 513 |
| Записей WI активировано | 73 (с проставлением sticky/cooldown в чате) | 0, скан не идёт |
| Куда попал промпт LBC | в конец последнего system-блока, после `<task>` Marinara («продолжи с последней реплики») и инструкции DES «в начале ответа — JSON трекера» | отдельным user-сообщением |
| Подключение | основное | профиль Connection Manager |

На проде контекст 1M, так что без модуля в каждую кнопку 🎲 уходит ещё больше.

Ещё три факта:

- **Макросы.** ST подставляет `{{user}}`/`{{char}}` в тихий промпт (`substituteParams`). LBC просит модель
  «сохранить макросы», но модель их уже не видит. «Enhance», «LLM Edit» и «Regenerate» навсегда заменяют
  `{{user}}` в записях именем персоны. **[стенд]** В сыром `quiet_prompt` из `GENERATION_STARTED` макросы на месте.
- **Тихий провал.** Если ответ не разобрался как JSON, LBC пишет «0 entries generated!» зелёным статусом.
- **Без стрима.** Тихие генерации идут без стрима (`type !== 'quiet'` в `Generate`). Ответ — один JSON, а значит,
  его можно подставить целиком.

### 3.1. Чистый канал — проверенная схема

**[стенд]** Прототип прямо в странице отработал так:

1. `GENERATION_STARTED`: тип `quiet`, не dry run, флаг `_lbcOwnGeneration` поднят, промпт похож на промпт LBC →
   запоминаем запрос и сырой промпт.
2. `WORLDINFO_ENTRIES_LOADED`: опустошаем списки книг. WI не сканируется, таймеры sticky/cooldown в чате не трогаются.
3. `CHAT_COMPLETION_PROMPT_READY` (последним): заменяем весь чат на `[system: наши правила, user: сырой промпт LBC]`.
4. `CHAT_COMPLETION_SETTINGS_READY` (последним): ставим на `generate_data` метку запроса.
5. Обёртка `fetch`: запрос на `/api/backends/chat-completions/generate` с нашей меткой отправляем через
   `ConnectionManagerRequestService.sendRequest(profileId, messages, …, {includePreset: false})` и возвращаем ST
   ответ `{choices: [{message: {content}}]}`. Остальные запросы, включая запрос самого профиля, проходят как есть.

Что доделать на этапе 2:

- Опознавать промпты LBC по сигнатурам всех 21 шаблона `[OOC: …` (18 в `PROMPTS`, `PROMPTS.optimizeKeys` и
  2 встроенных — строки 1294 и 1535), а не по одному флагу.
  Флаг глобальный, и параллельная генерация соседа не должна попасть под подмену.
- Для DeepSeek через OpenRouter профиль без пресета сам включает рассуждения (Maestro уже на это наступал).
  Нужна настройка reasoning (по умолчанию «нет»), лимит ответа по типу промпта (книга целиком — много, одно поле —
  мало) и таймаут со «Стопом».
- Без выбранного профиля: тот же чистый промпт и без WI, но через основное подключение.
- Только Chat Completion. Для Text Completion модуль предупреждает и не вмешивается.
- `json_schema` для ответов — по возможности (схема на каждый тип промпта), иначе LBC разбирает JSON сам.
- Провал разбора показываем ошибкой, а не «0 entries generated!»: ответ виден в нашем канале.

## 4. Импорт в ST и данные книги

`doImportToST` собирает книгу из своей модели записи и шлёт её на `/api/worldinfo/import`. Имя файла:
`name.replace(/[^a-zA-Z0-9_-]/g, '_')`.

**[стенд]** Подтверждено:

| Что | Результат |
| --- | --- |
| «Мир Тьмы» | файл `________.json`, а LBC пишет «"Мир Тьмы" imported!». Любые две русские книги одинаковой длины перезаписывают друг друга. |
| «Velmar Reaches», открытая в LBC и импортированная обратно | ложится рядом как `Velmar_Reaches`: пробел тоже заменяется. |
| Список книг ST | не обновляется до перезагрузки, кэш `worldInfoCache` не сбрасывается. |
| Бэкап перезаписываемой книги | нет. |

**[стенд]** Круг «открыть в LBC → импортировать» на синтетической книге:

| Поле | Было | Стало |
| --- | --- | --- |
| `uid` / `displayIndex` | 7, 12 | 0, 1 |
| `extensions` (маркеры Localizer, данные Maestro) | есть | **нет** |
| `role` у записи @D | 2 (assistant) | 0 (system) |
| `depth` / `order` / `probability` | 0 / 0 / 0 | 4 / 100 / 100 (`parseInt(x) \|\| default`) |
| `characterFilter`, `triggers`, `scanDepth`, `caseSensitive`, `vectorized`, `ignoreBudget`, `outletName`, `delayUntilRecursion` | заданы | сброшены |
| `cooldown`, `delay` | 0 | null |
| `category` | — | добавлено (ST его игнорирует) |

Кроме того, LBC подписывает позицию 4 как «System prompt», хотя это @D (на глубине) с ролью system.

### 4.1. Как будет в модуле

- Кнопку «Import to ST» перехватываем (capture) и сохраняем сами через `saveWorldInfo(name, data, true)`.
  Имя — как есть, с кириллицей и пробелами. Если книга существует — «Перезаписать / Сохранить копией»,
  перед перезаписью бэкап, после — обновление списка книг ST.
- Записи LBC сопоставляются с исходной книгой: название+текст → название → ключи. Из исходника возвращаются
  `uid`, `extensions`, роль и все поля, которых нет в модели LBC.
- При загрузке книги в LBC (кнопка, файл, `openWorld`) снимаем снимок. Если поле записи в LBC не менялось, при
  сохранении берём исходное значение. Это закрывает и баги с нулями.
- BunnyMo и паки (`isProtectedBook`) поверх не сохраняем. Для архивов CarrotKernel — предупреждение: там `key[0]` — имя.

## 5. Ключи и оптимизатор

- Все промпты генерации говорят «тот же язык, что идея/контекст». Ключи получаются на языке текста, и в русском RP
  английская книга не срабатывает.
- Оптимизатор (`lbcAudit`/`lbcAutoFix`, без LLM):
  - `LBC_GENERIC_KEYS` — 64 английских слова, русских нет;
  - `short_key` и Auto-Fix ставят `matchWholeWords` для ключей до 4 символов. На кириллице в ST эта галочка не
    работает (`\W` без `u`). Нужен regex-ключ с границами Unicode — то, что строит Localizer;
  - regex-ключи считаются обычными строками: пересечения словоформ (Анна/Анны) не видны, а Auto-Fix может
    навесить на запись с regex-ключами `matchWholeWords`;
  - токены считаются с поправкой на кириллицу (2,2 символа на токен), это нормально.
- Optimize (`lbcApplyPatches`) заменяет массив `key` целиком. LLM Edit по инструкции возвращает «полный обновлённый
  массив». В обоих случаях regex-ключи Localizer'а проходят через модель и теряются или портятся.
- Промпт оптимизатора: «Keep keys in the SAME LANGUAGE as the entry content».

## 6. Категории

- 14 встроенных категорий на английском. `canonicalizeCategory` знает только английские синонимы.
- Модель, которая пишет по-русски, отдаёт «Персонаж», «Локация» и т. п. Они становятся пользовательскими
  категориями: чипы фильтра дробятся, а Auto-Fix ставит всем `order` 300 вместо лестницы
  (Core Rule 1000 … Supplementary 100).
- Модуль: в правилах промпта — строго английские строки из списка; после ответа — русские синонимы сводятся к
  каноническим прямо в `lbcData.entries`. В интерфейсе категории показываются по-русски через словарь.

| Что | Сколько |
| --- | --- |

| Константы | 9 типов мира, 11 эпох, 5 ролей, 5 масштабов (подпись + описание), 14 категорий |
| Строки с числами | 12 шаблонов сообщений аудита, счётчики («N entries generated!», «N change(s) applied.» …) |

| Атрибуты | 26 `title=`, 6 `placeholder=` |

- Встроенный «перевод» LBC (`#lbc-h-tr`) гонит каждую подпись через Chat Translation (на сервере — Яндекс) и заодно
  машинно переводит содержимое записей. По решению Л4 кнопку прячем.
- «To English» (`#lbc-tr-idea`) переводит идею тем же Яндексом. В режиме «английский текст» это делает модель
  через наш канал, с сохранением имён.
- Перевод — по образцу DES-RU: словарь `locales/ru.lorebook-creator.json`, DOM-переводчик по корням
  `#lbc-panel` и четырём окнам. Поля ввода, тексты записей и названия не трогаем, шаблоны с числами — регулярками.
  Плюс утилита сверки словаря с новой версией LBC (`--missing` / `--stale`).
- `confirm`/`prompt` (решение Л5): пока открыта панель или окно LBC, подменяем `window.confirm/prompt`. Переводим
  только строки из словаря, остальное проходит как есть. У `bookImportReplace` смысл кнопок надо передать точно:
  «OK — заменить все, Отмена — добавить к текущим».

## 8. Черновик (решение Л8)

`lbcData` живёт только в памяти: перезагрузка страницы стирает работу. Модуль сохраняет черновик (`localforage`,
он есть в ST) по таймеру и при `pagehide`. При старте возвращает его в `lbcData` через `getData()`, панель
перерисовывается через `open()`. Служебные поля (`_trL`, `_translated`, `_orig*`) не сохраняем.

## 12. Для апстрима

Ошибки LBC, о которых стоит написать автору (не про русский язык):

- `generateQuietPrompt(prompt, false)`: `false` — это `quietToLoud`, в запрос уходит весь RP-контекст и WI;
- имя файла при импорте: `[^a-zA-Z0-9_-] → _` (кириллица, пробелы, коллизии);
- `parseInt(x) || default` превращает 0 в значение по умолчанию (`depth`, `order`, `probability`);
- импорт теряет `uid`, `extensions` и поля, которых нет в модели;
- «0 entries generated!» при неразобранном ответе;
- `window.LorebookCreator.version` = `'1.12.0'`.
